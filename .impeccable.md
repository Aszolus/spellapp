# SpellApp - Design Context

## Design Context

### Users

Pathfinder 2e tabletop players, ranging from casual players to rules-heavy optimizers. The app is used during character creation, between-session leveling, and live play at the table. Users may be in dim lighting, holding a phone or tablet in one hand while referencing dice, notes, or a physical sheet.

Primary jobs-to-be-done:
- Build a valid level-one character without missing required choices.
- Understand what each ancestry, heritage, background, class, feat, and skill choice grants before selecting it.
- Level a character while keeping future planning separate from active requirements.
- Use the character sheet as the source of truth during play.
- Quickly verify rules-derived facts such as attribute modifiers, HP, proficiencies, saves, skills, class DCs, and spell information.
- Browse spell details locally during play.
- Trust that the data is correct, explainable, and available offline.

### Brand Personality

**Fantasy. Precise. Tactical.**

- *Fantasy* - this is a character sheet and rules companion for a fantasy table, not a generic form editor.
- *Precise* - rules-exact. No rounding off, no vague validation, no unexplained derived stats.
- *Tactical* - optimized for decisions under time pressure. Dense is fine; unclear is not.

Emotional goals: confidence that the character is valid, calm focus while making rules choices, and a little sense of fantasy craft without sacrificing readability.

### Aesthetic Direction

**Arcane reference desk** - closer to a well-used character folio and rules notebook than a marketing site or game wiki. It should feel practical enough for table use and distinctive enough to belong to a fantasy RPG.

- Typography should support scanning long rules text and compact builder controls. Use distinctive display treatment sparingly for names and section headers; keep body and control text highly legible.
- Palette should stay quiet in the app chrome, with semantic color reserved for state, rarity, tradition, traits, warnings, and completion.
- Ornament is earned, not sprinkled. Rule-lines, subtle dividers, source notes, and compact tags are preferable to decorative frames, glow effects, or oversized cards.
- Both light and dark themes are required. Dark remains important for dim at-table lighting.

**Anti-references** - do not clone or echo:
- **D&D Beyond** - card-heavy marketing feel, big hero art, branded accents.
- **Foundry VTT** - dense developer/console aesthetic, tabbed admin panels.
- **Archives of Nethys** - wiki-style HTML tables, useful but visually flat.

The app should be instantly distinguishable from all three on first glance.

### Design Principles

1. **Rules where choices happen.** A user should not have to select a name-only option and hope the details work out later.
2. **Errors belong where they can be fixed.** A section should not show blockers for choices controlled somewhere else.
3. **Level one is a guided workflow.** Future planning belongs in the Level Workbench, not mixed into creation sections.
4. **The sheet is authoritative.** Sheet values should feel current, playable, and explainable, not like a report copied from another source.
5. **Readable in dim light, one-handed, under pressure.** Touch targets should be at least 48dp. Type hierarchy must support scanning without reading every line.
6. **Rules-exact over decorative.** If visual flourish competes with modifiers, proficiencies, actions, or source text, the rules win.
7. **Semantic theme tokens.** Colors and typography should flow through Material 3 roles so future themes can swap cleanly.
8. **Quiet chrome, loud content.** Navigation and surfaces stay restrained; the character choices, rules grants, and validation states carry the visual weight.

### Technical Constraints

- Android Jetpack Compose, Material 3, min SDK 28, target 35.
- Strictly offline: no network permission, no runtime HTTP clients, no remote fonts.
- Bundle any custom fonts or visual assets as app resources.
- Touch targets, contrast, and text fit are non-negotiable because of at-table use.
